# 系统架构说明 - 统一攻击系统
# System Architecture - Unified Attack System

## 概览 (Overview)

本文档解释了移除 `NormalAttackSystem` 后的系统架构，以及各系统如何协作处理角色功能。

This document explains the system architecture after removing `NormalAttackSystem` and how systems collaborate to handle character functionality.

## 核心系统 (Core Systems)

### 1. ModularAbilitySystem (模块化能力系统)

**职责 (Responsibilities):**
- 处理所有攻击能力（轻攻击、重攻击）
- 处理防御能力
- 处理特殊技能
- 管理能力优先级
- 检查能力解锁状态

**工作流程 (Workflow):**
```
1. 获取实体的 ModularCharacterConfig
   ↓
2. 如果没有配置，跳过（向后兼容）
   ↓
3. 收集所有激活的能力（基于输入）
   ↓
4. 按优先级排序
   ↓
5. 执行最高优先级的能力
   ↓
6. 触发事件（AttackPerformed, SpecialMovePerformed等）
```

**关键特性:**
- ✅ 支持轻攻击连招系统
- ✅ 支持重攻击蓄力系统
- ✅ 支持特殊技能指令输入
- ✅ 基于优先级的能力执行
- ✅ 等级解锁系统

### 2. MovementSystem (移动系统)

**职责 (Responsibilities):**
- 处理角色移动
- 管理跳跃和冲刺
- 根据等级解锁移动能力
- 更新面向方向

**配置支持:**
- 优先使用 `ModularCharacterConfig`（如果存在）
- 向后兼容 `CharacterAttackConfig`
- 根据配置启用/禁用二段跳
- 根据配置启用/禁用冲刺

**关键方法:**
```csharp
// 获取修改后的KCC设置（考虑解锁状态）
GetModifiedSettingsByUnlocks()

// 过滤未解锁的输入
FilterInputByUnlocks()

// 检查能力是否解锁（模块化配置）
IsAbilityUnlocked()
```

### 3. CommandInputSystem (指令输入系统)

**职责 (Responsibilities):**
- 追踪玩家输入序列
- 维护输入缓冲区
- 提供输入匹配功能

**用途:**
- 用于特殊技能的指令输入检测
- 例如：236LP (↓↘→LP) 波动拳

**配置依赖:**
- 使用 `CharacterAttackConfig` 的配置参数
  - `CommandInputWindow`: 指令窗口时间
  - `MaxInputBufferSize`: 缓冲区大小

**关键方法:**
```csharp
// 检查输入序列是否匹配
static bool MatchesSequence(CommandInputData*, int[] sequence)

// 清空输入缓冲区
static void ClearInputBuffer(CommandInputData*)
```

### 4. LevelUpSystem (等级系统)

**职责 (Responsibilities):**
- 管理角色等级
- 触发升级事件

**与能力系统的集成:**
- 能力可以设置 `RequiredLevel`
- `ModularAbilitySystem` 检查等级要求
- 等级解锁与 `AbilityUnlocks` 数组配合

## 配置架构 (Configuration Architecture)

### AttackData 组件 (AttackData Component)

```qtn
component AttackData
{
    // 传统配置（用于输入缓冲等）
    asset_ref<CharacterAttackConfig> AttackConfig;
    
    // 模块化配置（用于能力执行）
    asset_ref<ModularCharacterConfig> ModularConfig;
    
    // 运行时状态
    [ExcludeFromPrototype] Int32 ComboCounter;
    [ExcludeFromPrototype] FrameTimer ComboResetTimer;
    [ExcludeFromPrototype] FrameTimer AttackCooldown;
    [ExcludeFromPrototype] bool IsAttacking;
    [ExcludeFromPrototype] FP HeavyChargeTime;
    [ExcludeFromPrototype] bool IsChargingHeavy;
}
```

### 配置使用策略 (Configuration Usage Strategy)

#### CharacterAttackConfig (传统配置)
**使用场景:**
- `CommandInputSystem` 的输入缓冲设置
- `MovementSystem` 的能力解锁等级（如果没有ModularConfig）

**保留原因:**
- 向后兼容现有角色
- 一些通用设置仍然有用

#### ModularCharacterConfig (模块化配置)
**使用场景:**
- `ModularAbilitySystem` 的能力执行
- `MovementSystem` 的能力解锁检查（优先）

**优势:**
- 更灵活的能力组合
- 支持多种能力类型
- 易于扩展

## 能力优先级系统 (Ability Priority System)

### 优先级范围 (Priority Ranges)

```
200+    : 超级技能 (Ultimate Abilities)
100-199 : 特殊技能 (Special Abilities)
50-99   : 重攻击 (Heavy Attacks)
30-49   : 防御技能 (Defense Abilities)
10-29   : 轻攻击 (Light Attacks)
0-9     : 移动技能 (Movement Abilities)
```

### 执行规则 (Execution Rules)

1. **每帧只执行一个能力**
   - 系统收集所有可执行的能力
   - 按优先级降序排序
   - 执行第一个（最高优先级）

2. **输入检查**
   - 每个能力定义所需的输入
   - 系统检查当前输入是否匹配
   - 只考虑输入匹配的能力

3. **解锁检查**
   - 检查角色等级是否满足 `RequiredLevel`
   - 检查能力是否在 `AbilityUnlocks` 中解锁
   - `UnlockedByDefault` 为true的能力总是可用

## 数据流 (Data Flow)

### 攻击执行流程 (Attack Execution Flow)

```
Player presses LP button
    ↓
Input captured by Frame
    ↓
ModularAbilitySystem.Update()
    ↓
GetModularConfig() - 获取配置
    ↓
ProcessAbilitiesByPriority()
    ↓
遍历 AttackAbilities
    ↓
检查输入匹配 (ShouldExecuteAttackAbility)
    ↓
检查等级要求 (IsAbilityUnlocked)
    ↓
添加到执行列表
    ↓
按优先级排序
    ↓
ExecuteAttackAbility()
    ↓
- 更新 ComboCounter
- 计算伤害
- 设置冷却
- 触发事件
    ↓
frame.Events.AttackPerformed()
```

### 特殊技能执行流程 (Special Move Execution Flow)

```
Player inputs: ↓↘→LP
    ↓
CommandInputSystem tracks sequence
    ↓
Input buffer: [Down, DownRight, Right, LP]
    ↓
ModularAbilitySystem checks SpecialAbilities
    ↓
MatchesSequence() returns true
    ↓
ExecuteSpecialAbility()
    ↓
- 清空输入缓冲
- 设置冷却
- 触发事件
    ↓
frame.Events.SpecialMovePerformed()
```

## 向后兼容策略 (Backward Compatibility Strategy)

### 场景 1: 仅有 CharacterAttackConfig

```
AttackData:
  AttackConfig: ✅ LegacyConfig
  ModularConfig: ❌ null

结果:
- ModularAbilitySystem: 跳过（返回null）
- CommandInputSystem: ✅ 正常工作
- MovementSystem: ✅ 使用 AttackConfig 的解锁设置
```

### 场景 2: 同时有两种配置

```
AttackData:
  AttackConfig: ✅ LegacyConfig
  ModularConfig: ✅ NewConfig

结果:
- ModularAbilitySystem: ✅ 使用 ModularConfig
- CommandInputSystem: ✅ 使用 AttackConfig 设置
- MovementSystem: ✅ 优先使用 ModularConfig 的解锁
```

### 场景 3: 仅有 ModularCharacterConfig

```
AttackData:
  AttackConfig: ⚠️ 需要保留（用于输入缓冲设置）
  ModularConfig: ✅ NewConfig

建议:
- 保留一个基础的 AttackConfig
- 或修改 CommandInputSystem 支持从 ModularConfig 读取
```

## 性能考虑 (Performance Considerations)

### 优化点 (Optimizations)

1. **早期返回 (Early Returns)**
   ```csharp
   // 如果没有 ModularConfig，立即返回
   if (modularConfig == null) return;
   
   // 如果在冷却中，立即返回
   if (cooldown.IsRunning(frame)) return;
   ```

2. **优先级排序**
   - 使用 `List.Sort()` 进行排序
   - 能力数量通常很少（<10个）
   - 性能影响可忽略

3. **按需加载**
   - 只加载实体实际引用的能力
   - 使用 `AssetRef` 延迟加载

### 内存使用 (Memory Usage)

- 能力组件是共享资源（AssetObject）
- 多个角色可以引用同一个能力组件
- 运行时状态存储在组件中（AttackData等）

## 扩展指南 (Extension Guide)

### 添加新能力类型 (Adding New Ability Type)

1. **创建新的能力组件类**
   ```csharp
   public class UtilityAbilityComponent : AbilityComponentBase
   {
       public UtilityAbilityType UtilityType;
       // ... 其他属性
   }
   ```

2. **扩展 ModularCharacterConfig**
   ```csharp
   public AssetRef<UtilityAbilityComponent>[] UtilityAbilities;
   ```

3. **在 ModularAbilitySystem 中处理**
   ```csharp
   if (config.UtilityAbilities != null)
   {
       // 处理 utility abilities
   }
   ```

### 添加新的输入类型 (Adding New Input Type)

1. **扩展 SimpleInput2D**（在Quantum层）
2. **更新 ShouldExecuteAttackAbility** 等方法
3. **在能力组件中添加新的触发条件**

## 调试技巧 (Debugging Tips)

### 检查能力是否被执行

1. **查看日志**
   ```
   "Modular Attack: [AbilityName] - Type: [Type], Damage: [Value]"
   "Modular Special: [AbilityName] - Type: [Type], Damage: [Value]"
   ```

2. **检查配置**
   - ModularConfig 是否正确引用
   - AttackAbilities 数组是否有元素
   - 能力的 Priority 值

3. **检查输入匹配**
   - 在 `ShouldExecuteAttackAbility` 添加调试日志
   - 确认输入按钮映射正确

4. **检查解锁状态**
   - 确认 CharacterLevel 组件存在
   - 检查 RequiredLevel 是否满足
   - 查看 AbilityUnlocks 数组

## 总结 (Summary)

移除 `NormalAttackSystem` 后的架构：
- ✅ 更简洁：只有一个系统处理所有攻击
- ✅ 更灵活：能力优先级和组合系统
- ✅ 向后兼容：现有角色继续工作
- ✅ 易于扩展：添加新能力类型很简单
- ✅ 符合Quantum：模块化、确定性、可组合

The architecture after removing `NormalAttackSystem` is cleaner, more flexible, backward compatible, easy to extend, and aligned with Quantum's principles.
